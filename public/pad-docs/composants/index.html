    Composants¶

    Cette section documente chaque brique technologique de la plateforme, une page par brique, avec la même structure : à quoi elle sert ici et pourquoi ce choix, où elle tourne, version épinglée (et où), fichiers de configuration, interactions, sécurité, supervision, opérations courantes, pièges connus et lien vers la documentation officielle. Pour le récit de bout en bout, commencer par Comment tout fonctionne ; pour les décisions, voir les ADR.

    Lire cette documentation en local

    task docs:serve    # aperçu sur http://127.0.0.1:8000, rechargement automatique
task docs:build    # mkdocs build --strict (identique à la CI), sortie dans site/
    Les deux tâches créent le venv .venv-docs et y installent docs/requirements.txt (versions exactes) s'il est absent ou périmé. Sans task : python3 -m venv .venv-docs && .venv-docs/bin/pip install -r docs/requirements.txt && .venv-docs/bin/mkdocs serve.

    Les versions viennent du dépôt (contrat, versions.yml, Chart, package.json...) ; le chemin exact est donné dans chaque page. Renovate les maintient à jour (page).

    Proxmox VE Hyperviseur : VM, LXC, stockage ZFS, bridges hôte bare metal (le seul serveur) 9.x (prérequis, non piloté par le dépôt)

    Provider goauthentik/authentik Déclare dans Authentik les groupes du contrat, les providers OAuth2 et applications (un par client OIDC), les flows d'inscription joueur et staff, les stages (captcha, e-mail, mot de passe) et le provider proxy (forward-auth) des interfaces internes poste opérateur (via OpenTofu) 2026.8.0
    Provider netbirdio/netbird Configure NetBird : groupes, networks (pad-instances, pad-bastion), routing peers, clés d'installation, connecteur d'identité Authentik, utilisateur de service pour netbird-sync et policy staff vers bastion poste opérateur (via OpenTofu) 0.0.10
    Provider warp-tech/warpgate Crée dans Warpgate un rôle par groupe d'accès (défaut infra-admins) et les cibles SSH (LXC, OPNsense, hôte) et HTTP (UI OPNsense, UI Proxmox), rattachées à ces rôles poste opérateur (via OpenTofu) 1.2.0
    Provider ovh/ovh Publie les enregistrements DNS A publics (front, auth, vpn, status) vers l'IP WAN de la plateforme poste opérateur (via OpenTofu) 2.22.0
    Provider carlpett/sops Lit les fichiers `* poste opérateur (via OpenTofu) 1.4.1
    Ansible Configure l'hôte Proxmox et déploie les services Docker Compose des LXC poste opérateur (connexion SSH vers l'hôte et les LXC) collections épinglées (voir ci-dessous) ; ansible du devshell
    OPNsense Routeur, pare-feu inter-zones, DNS interne, IDS VM Proxmox (VMID 200, 2 vCPU, 1,5 Go) 25.7 (image nano épinglée par sha256)
