**Terraform** provisionne l'infrastructure (VMs, réseaux, DNS). **Ansible** la configure (packages, services, utilisateurs). Ces deux outils sont complémentaires et forment ensemble le socle d'une démarche Infrastructure as Code robuste, de votre homelab jusqu'au cloud public.

## Terraform : l'infrastructure déclarative

Terraform utilise HCL (HashiCorp Configuration Language) pour décrire l'état désiré de votre infrastructure. Son moteur de planification calcule le diff entre l'état courant et l'état désiré, puis applique uniquement les changements nécessaires. Le **state file** — à stocker en remote (S3, Terraform Cloud) — garde trace de l'état réel.

```hcl
# main.tf — Exemple Proxmox + Terraform
terraform {
  required_providers {
    proxmox = {
      source  = "bpg/proxmox"
      version = "~> 0.46"
    }
  }
}

resource "proxmox_virtual_environment_vm" "k8s_node" {
  count     = 3
  name      = "k8s-node-${count.index + 1}"
  node_name = "pve01"
  cpu { cores = 4 }
  memory { dedicated = 8192 }
}
```

## Ansible : la configuration idempotente

Un playbook Ansible bien écrit est **idempotent** : on peut le rejouer plusieurs fois sans effets de bord. Utilisez des **roles** pour organiser votre code et **molecule** pour tester vos rôles dans des containers avant de les déployer. L'inventaire dynamique permet de cibler automatiquement les VMs créées par Terraform.

> Combinez Terraform et Ansible via un `null_resource` avec un `remote-exec` provisioner — ou mieux, via un pipeline CI/CD GitLab qui exécute d'abord `terraform apply` puis `ansible-playbook` sur le nouvel inventaire.
