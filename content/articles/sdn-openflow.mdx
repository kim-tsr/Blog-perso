Le **Software-Defined Networking** dissocie le plan de contrôle du plan de données. Plutôt que de configurer chaque équipement individuellement, un contrôleur central programme les règles de flux sur l'ensemble des switches et routers. OpenFlow est le protocole de communication entre le contrôleur et les équipements.

## Architecture d'un réseau SDN

On distingue trois plans dans un réseau SDN. Le **plan de données** (dataplane) correspond aux équipements physiques ou virtuels qui forwardent les paquets. Le **plan de contrôle** est centralisé dans le contrôleur SDN. Le **plan de gestion** gère la configuration et le monitoring.

```bash
# Installer Open vSwitch
apt install openvswitch-switch

# Créer un bridge OVS
ovs-vsctl add-br br-sec

# Connecter le bridge au contrôleur
ovs-vsctl set-controller br-sec \
  tcp:192.168.1.100:6633

# Vérifier la connexion
ovs-vsctl show
```

## OpenDaylight et ONOS

**OpenDaylight** et **ONOS** sont les deux contrôleurs open source les plus matures. ONOS brille particulièrement dans les environnements carrier-grade avec ses garanties de haute disponibilité. OpenDaylight offre un écosystème de plugins très riche pour les cas d'usage enterprise.

> Dans un contexte DevSecOps, le SDN permet de programmer dynamiquement des règles de quarantaine : dès qu'une alerte SIEM se déclenche, le contrôleur peut isoler automatiquement le segment réseau suspect.

## P4 : le futur du dataplane programmable

Au-delà d'OpenFlow, le langage **P4** permet de programmer le comportement du dataplane lui-même — pas seulement les règles de forwarding, mais le traitement des paquets à un niveau très bas. Les smartNICs et certains ASICs modernes supportent P4, ouvrant des possibilités inédites pour l'inspection et la transformation de trafic en temps réel.
