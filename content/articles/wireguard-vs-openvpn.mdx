Le VPN reste un composant fondamental de l'accès sécurisé à un lab ou une infrastructure distante. **WireGuard**, intégré au kernel Linux depuis la version 5.6, s'est imposé comme une alternative moderne et performante à **OpenVPN**. Mais lequel choisir selon votre usage ?

## WireGuard : la modernité et la performance

WireGuard représente ~4000 lignes de code C (vs ~70 000 pour OpenVPN), ce qui facilite drastiquement son audit de sécurité. Il repose sur une cryptographie moderne et figée : **ChaCha20** pour le chiffrement, **Curve25519** pour l'échange de clés, **Poly1305** pour l'authenticité. Pas de négociation d'algorithme, pas de surface d'attaque liée à une mauvaise configuration crypto.

```ini
# /etc/wireguard/wg0.conf — Serveur
[Interface]
PrivateKey = <SERVER_PRIVATE_KEY>
Address    = 10.0.0.1/24
ListenPort = 51820

[Peer]
PublicKey  = <CLIENT_PUBLIC_KEY>
AllowedIPs = 10.0.0.2/32
```

```bash
# Activer WireGuard
wg-quick up wg0
```

## OpenVPN : la flexibilité et l'écosystème

OpenVPN reste pertinent pour les environnements qui nécessitent une **compatibilité large** (clients anciens, équipements réseau tiers), une **traversée fine de firewalls** (TCP/443 est rarement bloqué), ou des fonctionnalités avancées comme les CRL et la révocation de certificats granulaire.

> Pour un lab DevSecOps personnel, choisissez WireGuard sans hésitation. Pour une PKI d'entreprise avec gestion de certificats et révocation, OpenVPN reste plus adapté — ou explorez Tailscale qui abstrait WireGuard avec une couche de gestion des identités.
