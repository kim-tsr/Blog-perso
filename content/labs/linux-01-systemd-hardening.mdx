## 🧠 Théorie : un service systemd, c'est quoi exactement ?

```
   /etc/systemd/system/myapp.service       ← l'unit (config déclarative)
              │
              ▼
   systemctl start myapp
              │
              ▼
   PID 1 (systemd) fork + apply directives:
       ┌────────────────────────────────────┐
       │  setuid(www-data)                  │
       │  setns(mount/pid/net/...) si dirs  │
       │  cgroup v2 placement               │
       │  apply NoNewPrivileges             │
       │  apply RestrictAddressFamilies     │
       │  apply seccomp filter              │
       │  exec /usr/bin/myapp               │
       └────────────────────────────────────┘
              │
              ▼
   Le process tourne dans une jail
   construite par systemd, sans
   que le code app ait été touché.
```

### Anatomie minimale d'une unit

```ini
[Unit]
Description=My App
After=network.target

[Service]
ExecStart=/usr/bin/myapp
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

C'est minimal mais **pas sécurisé** : tourne en root, voit tout le filesystem, peut faire setuid, ouvrir n'importe quel port, faire du raw socket, etc.

### Catalogue des directives de sandboxing (les essentielles)

| Directive | Effet |
|---|---|
| `User=`, `Group=` | Drop vers un user dédié sans shell |
| `DynamicUser=true` | systemd crée un UID éphémère unique (encore mieux) |
| `NoNewPrivileges=true` | Bloque setuid/file capabilities |
| `ProtectSystem=strict` | / en read-only sauf /dev /proc /sys |
| `ProtectHome=true` | Cache /home /root /run/user |
| `PrivateTmp=true` | /tmp namespacé privé |
| `PrivateDevices=true` | Pas d'accès aux devices physiques |
| `PrivateNetwork=true` | Pas de réseau du tout (utile pour batch local) |
| `ProtectKernelTunables=true` | /proc/sys et /sys read-only |
| `ProtectKernelModules=true` | Pas de modprobe |
| `ProtectControlGroups=true` | cgroups read-only |
| `RestrictAddressFamilies=AF_INET AF_INET6` | Whitelist familles socket |
| `RestrictNamespaces=true` | Pas de unshare/clone |
| `LockPersonality=true` | Bloque le syscall personality (anti-bypass ASLR) |
| `MemoryDenyWriteExecute=true` | W^X enforcé (anti-shellcode) |
| `SystemCallFilter=@system-service` | Allowlist de syscalls (seccomp) |
| `CapabilityBoundingSet=` | Whitelist des capabilities (vide = aucune) |
| `ReadOnlyPaths=`, `ReadWritePaths=` | Override granulaire du FS |

## 🎯 Objectif

Partir d'un service basique non sécurisé. Le sandboxer étape par étape. Mesurer le score `systemd-analyze security` avant/après.

## 📋 Étape 1 — Un service simple non sécurisé

```bash
# Une "app" : un petit serveur Python
sudo tee /usr/local/bin/myapp <<'EOF'
#!/usr/bin/env python3
from http.server import BaseHTTPRequestHandler, HTTPServer
class H(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header('Content-Type', 'text/plain')
        self.end_headers()
        self.wfile.write(b'hello from myapp\n')
HTTPServer(('127.0.0.1', 8080), H).serve_forever()
EOF
sudo chmod +x /usr/local/bin/myapp
```

Unit naïve :

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My App (non sécurisé)
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
curl http://127.0.0.1:8080/   # → "hello from myapp"
```

Mesurez la dette de sécurité :

```bash
sudo systemd-analyze security myapp
```

→ score autour de **9.6 UNSAFE**. Le rapport liste tout ce qui n'est pas activé.

## 📋 Étape 2 — Premier durcissement : isolation de base

```ini
[Service]
ExecStart=/usr/local/bin/myapp
Restart=on-failure

# User dédié et dynamique (UID éphémère unique)
DynamicUser=true

# Empêche toute escalade par setuid binary
NoNewPrivileges=true

# Filesystem : / read-only, $TMPDIR privé
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
ProtectKernelTunables=true
ProtectKernelLogs=true
ProtectKernelModules=true
ProtectControlGroups=true
ProtectClock=true
ProtectHostname=true
ProtectProc=invisible
ProcSubset=pid
```

```bash
sudo systemctl daemon-reload
sudo systemctl restart myapp
sudo systemd-analyze security myapp
```

Score qui plonge vers **3-4**. Mais on n'a pas fini.

## 📋 Étape 3 — Réseau et namespaces

```ini
# Whitelist familles socket : pas de raw, pas de netlink, pas d'AF_UNIX externe
RestrictAddressFamilies=AF_INET AF_INET6

# Pas de namespaces utilisables → bloque toute évasion via unshare
RestrictNamespaces=true

# Pas de SUID/SGID dans les fichiers créés
RestrictSUIDSGID=true

# Pas de personality() (anti-bypass ASLR)
LockPersonality=true

# Pas de mmap PROT_WRITE|PROT_EXEC (anti-shellcode)
MemoryDenyWriteExecute=true
```

## 📋 Étape 4 — Capabilities et syscalls

```ini
# AUCUNE capability (notre app n'en a besoin d'aucune)
CapabilityBoundingSet=
AmbientCapabilities=

# Seccomp : allowlist par "set" syscall systemd
SystemCallFilter=@system-service
SystemCallFilter=~@privileged @resources
SystemCallErrorNumber=EPERM
SystemCallArchitectures=native
```

> 💡 `@system-service` couvre 99% des besoins d'un service userland (read/write/poll/etc). Les `~@privileged @resources` retirent les sous-ensembles dangereux (`ptrace`, `mount`, `setns`, `unshare`, `bpf`, `chroot`).

## 📋 Étape 5 — FS write granulaire

Si l'app doit écrire (logs, cache) :

```ini
# Whitelist write
StateDirectory=myapp           # /var/lib/myapp (créé + chown auto)
CacheDirectory=myapp           # /var/cache/myapp
LogsDirectory=myapp            # /var/log/myapp
RuntimeDirectory=myapp         # /run/myapp (volatile)

# OU explicite :
# ReadWritePaths=/var/lib/myapp
```

> ⚠️ **Évite `ReadWritePaths=/var/log`** : trop large. Préfère `LogsDirectory` qui crée juste `/var/log/myapp`.

## 📋 Étape 6 — Unit finale et score

```ini
[Unit]
Description=My App (hardened)
After=network.target

[Service]
ExecStart=/usr/local/bin/myapp
Restart=on-failure

DynamicUser=true
NoNewPrivileges=true

ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
ProtectKernelTunables=true
ProtectKernelLogs=true
ProtectKernelModules=true
ProtectControlGroups=true
ProtectClock=true
ProtectHostname=true
ProtectProc=invisible
ProcSubset=pid

RestrictAddressFamilies=AF_INET AF_INET6
RestrictNamespaces=true
RestrictRealtime=true
RestrictSUIDSGID=true
LockPersonality=true
MemoryDenyWriteExecute=true

CapabilityBoundingSet=
AmbientCapabilities=

SystemCallFilter=@system-service
SystemCallFilter=~@privileged @resources
SystemCallErrorNumber=EPERM
SystemCallArchitectures=native

StateDirectory=myapp
LogsDirectory=myapp

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl restart myapp
sudo systemd-analyze security myapp
```

→ score typiquement **0.8-1.5 OK** (ou mieux). Compare avec le départ à 9.6.

## 🧠 Pitfalls courants

❌ **Mettre toutes les directives d'un coup et débugger** : restart par restart, observe les `journalctl -u myapp` pour comprendre quel filtre tue ton service.
❌ **`CapabilityBoundingSet=CAP_NET_BIND_SERVICE` pour binder port 80** : non, utilise `AmbientCapabilities=` ou délègue à un reverse proxy.
❌ **`PrivateNetwork=true` puis chercher pourquoi Redis ne répond pas** : ce flag coupe TOUT le réseau, même localhost vers un autre namespace.
❌ **Oublier `daemon-reload`** : la modif d'unit reste invisible jusqu'à là.
❌ **Penser que ces protections remplacent l'audit du code** : non, elles limitent les dégâts. Le code reste à auditer.

## 🔬 Validation

```bash
# 1. Le service tourne toujours
curl http://127.0.0.1:8080/

# 2. Tentative d'écriture sur / → refusée
sudo systemctl exec myapp -- /bin/sh -c 'echo x > /etc/x' 2>&1
# → Read-only file system

# 3. Tentative de syscall interdit
# (depuis le process : impossible sans modifier le code, mais le filter est actif)

# 4. systemd-analyze
sudo systemd-analyze security myapp
# → score ≤ 2 OK
```

## 🚀 Pour aller plus loin

- Étudie ton SystemCallFilter avec **strace** sur le process pour voir si certains syscalls sont bloqués
- Vérifie l'effet avec **bpftrace** : `bpftrace -e 'tracepoint:syscalls:sys_enter_* / pid == X / { @[probe] = count(); }'`
- Génère automatiquement les directives avec **systemd-analyze security --json | jq**
- Pour un projet d'envergure : couple avec **AppArmor / SELinux** (cf. lab #3 de la série)
