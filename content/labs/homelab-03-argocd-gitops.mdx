## 🧠 Théorie : qu'est-ce que GitOps exactement ?

GitOps n'est pas "j'ai mis mes YAML sur GitHub". C'est une **discipline opérationnelle** définie par 4 principes (OpenGitOps) :

| # | Principe | Implication |
|---|---|---|
| 1 | **Déclaratif** | On décrit *ce qu'on veut*, pas *comment l'obtenir*. YAML > scripts impératifs. |
| 2 | **Versionné et immutable** | Git est la source de vérité unique. Toute modif passe par un commit. |
| 3 | **Pulled automatiquement** | Un agent dans le cluster pull l'état désiré. Pas de push externe. |
| 4 | **Réconciliation continue** | L'agent compare en boucle observé vs. désiré et corrige. |

### Push CI/CD vs Pull GitOps

```
   Push (Jenkins, GitHub Actions → kubectl)

   ┌────────────┐  kubectl apply   ┌─────────────┐
   │ CI runner  │ ───────────────► │ Kubernetes  │
   │            │   (credentials)  │  API        │
   └────────────┘                  └─────────────┘
        ▲
        │ trigger
        │
   ┌────────────┐
   │   Git      │
   └────────────┘

   ⚠️  CI a un kubeconfig → si compromis, cluster compromis


   Pull (ArgoCD, Flux)

   ┌────────────┐                  ┌─────────────┐
   │   Git      │ ◄────────── pull │  ArgoCD     │ in-cluster
   │            │                  │   Agent     │
   └────────────┘                  └──────┬──────┘
                                          │ kubectl apply (local)
                                          ▼
                                   ┌─────────────┐
                                   │ Kubernetes  │
                                   │  API        │
                                   └─────────────┘

   ✅  Aucun credential cluster exposé hors du cluster
```

## 📋 Étape 1 — Installer ArgoCD

```bash
kubectl create namespace argocd
kubectl apply -n argocd \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl wait --for=condition=available --timeout=300s \
  -n argocd deployment/argocd-server

# Mot de passe initial
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d ; echo
```

Port-forward pour accéder à l'UI :

```bash
kubectl port-forward -n argocd svc/argocd-server 8080:443 --address=0.0.0.0
```

→ https://192.168.1.20:8080 (login : `admin`).

Contenu de `deployment.yaml` :

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: whoami
  namespace: demo
spec:
  replicas: 2
  selector: { matchLabels: { app: whoami } }
  template:
    metadata: { labels: { app: whoami } }
    spec:
      containers:
        - name: whoami
          image: traefik/whoami:v1.10
          ports: [ { containerPort: 80 } ]
          resources:
            requests: { cpu: 50m, memory: 32Mi }
            limits:   { cpu: 200m, memory: 128Mi }
```

Commit + push.

## 📋 Étape 3 — Connecter le dépôt à ArgoCD

```yaml
# argocd-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: whoami
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/<ton-user>/homelab-gitops.git
    targetRevision: main
    path: apps/whoami
  destination:
    server: https://kubernetes.default.svc
    namespace: demo
  syncPolicy:
    automated:
      prune: true       # supprime ce qui n'est plus en Git
      selfHeal: true    # ramène l'état du cluster vers Git
    syncOptions:
      - CreateNamespace=true
```

```bash
# Nettoie d'abord le déploiement manuel du Lab #2
kubectl delete -n demo deployment whoami
kubectl delete -n demo service whoami

# Applique
kubectl apply -f argocd-app.yaml
```

## 📋 Étape 4 — Tester la self-healing

```bash
kubectl scale -n demo deployment whoami --replicas=5
kubectl -n demo get deploy whoami        # → 5 replicas
# attendre 1-3 min
kubectl -n demo get deploy whoami        # → 2 replicas (ArgoCD a recollé)
```

### Cycle de réconciliation visualisé

```
   t=0s     git push
              │
   t=10s     ArgoCD repo-server poll
              │
   t=15s     compute diff désiré ↔ observé
              │
   t=20s     APPLY changements via API server
              │
   t=25s     Kubernetes converge → état Healthy
              │
   t=180s    nouveau cycle (boucle infinie)
```

## 📋 Étape 5 — Rollback par revert Git

Modifie `deployment.yaml` en Git : remplace `image: traefik/whoami:v1.10` par `image: nginx:1.27`. Commit + push. ArgoCD redéploie.

Tu n'aimes pas ?

```bash
git revert HEAD
git push
```

→ ArgoCD remet `whoami`. **Ton `git log` est ton historique de production.**

## 🧠 Pourquoi le pattern app-of-apps

```
homelab-gitops/
├── bootstrap/
│   └── root-app.yaml    ← Application qui pointe vers apps/
└── apps/
    ├── whoami.yaml      ← Application whoami
    ├── monitoring.yaml  ← Application prometheus (lab #4)
    └── falco.yaml       ← Application falco (lab #5)
```

Tu appliques `root-app.yaml` une seule fois → ArgoCD découvre les Applications et les déploie en cascade. On l'utilisera aux Labs #4 et #5.
