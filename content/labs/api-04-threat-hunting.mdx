## 🧠 Théorie : detection-as-code et la pyramide de Bianco

### La "Pyramid of Pain" de David Bianco

Ce que tu détectes définit combien tu fais souffrir l'attaquant pour s'adapter :

```
        ▲  TTPs / comportement      ┃  ━━━ DOULOUREUX
        │  (T1110 brute force)      ┃       (refactor d'attaque)
        │                            ┃
   ┃ Tools (cobalt strike, mimikatz) ┃  ━━━ ÉLEVÉ
   ┃                                  ┃
   ┃ Network artifacts (User-Agent)   ┃  ━━━ ANNOYANT
   ┃                                  ┃
   ┃ Host artifacts (file hash)       ┃  ━━━ FACILE
   ┃                                  ┃
   ┃ Domain names                     ┃  ━━━ TRIVIAL
   ┃                                  ┃
   ┃ IP addresses                     ┃  ━━━ TRIVIAL
   ┃                                  ┃
   ┃ Hash values                      ┃  ━━━ TRIVIAL  (1 byte change → différent)
   ▼                                   ━━━
```

**Détecter sur des IP ou hashes :** l'attaquant change → tu rates. **Détecter sur des comportements (3 logins ratés puis 1 réussi puis création d'admin) :** l'attaquant doit changer toute sa méthode.

## 📋 Règle 1 — Brute force sur l'authentification

**MITRE** : T1110.001 (Password Guessing)

```yaml
# rules/detection.yaml — format Loki alerting
groups:
  - name: api-security
    rules:
      - alert: ApiBruteForce
        expr: |
          sum by (ip) (
            count_over_time({app="api"} | json | event="auth.failure" [5m])
          ) > 30
        for: 1m
        labels:
          severity: high
          mitre_tactic: credential_access
          mitre_technique: T1110.001
        annotations:
          summary: "Brute force suspect depuis {{ $labels.ip }}"
          runbook: "Vérifier whois IP, bloquer au firewall si confirmé"
```

### Simulation : on attaque

```bash
# Avec hydra (apt install hydra)
hydra -l alice -P /usr/share/wordlists/rockyou.txt -t 4 \
```

## 📋 Règle 2 — Énumération de comptes

**MITRE** : T1087 (Account Discovery)

Symptôme : beaucoup d'IPs différentes, beaucoup d'users testés, peu de hits par user.

```logql
# Nombre d'users distincts essayés par IP en 10min
count by (ip) (
  count_over_time({app="api"} | json | event="auth.failure" [10m])
) > 50
```

Ou plus subtil — un seul attaquant testant beaucoup d'users :

```logql
sum by (ip) (
  count_over_time({app="api"} | json | event="auth.failure" | line_format "{{.user}}" [10m])
)
```

## 📋 Règle 3 — RBAC denied en série (recon de permissions)

**MITRE** : T1087.004 (Cloud Account Discovery)

Quand un user authentifié tente d'accéder à 10+ endpoints sans permission en 5 min → il scanne, pas une faute de clic.

```logql
sum by (user) (
  count_over_time({app="api"} | json | event="rbac.denied" [5m])
) > 10
```

## 📋 Règle 4 — Privilege escalation après login

**MITRE** : T1078 (Valid Accounts) suivi de T1098 (Account Manipulation)

Pattern à détecter : `auth.success` puis `rbac.granted` sur `users:write` ou `admin:*` dans les 5 minutes pour un user qui n'a jamais touché à ces endpoints avant.

Cette détection est plus complexe — généralement on l'écrit en code (Python + Loki) plutôt qu'en LogQL pur :

```python
# detector/escalation.py
for user, events in group_by_user(last_5_min):
    if 'admin:create' in events and user not in known_admins:
        alert(f"Suspicious admin action by non-admin user: {user}")
```

## 📋 Règle 5 — Anomaly detection par baseline

**Approche** : on calcule la moyenne et l'écart-type des erreurs sur 7 jours, on alerte sur écart > 3σ.

```logql
# Si le taux d'erreur 4xx sur 5min > moyenne 7j + 3 écarts-types
(
  sum(rate({app="api"} | json | status>=400 | status<500 [5m]))
)
>
(
  avg_over_time(
    sum(rate({app="api"} | json | status>=400 | status<500 [5m]))[7d:5m]
  )
  + 3 *
  stddev_over_time(
    sum(rate({app="api"} | json | status>=400 | status<500 [5m]))[7d:5m]
  )
)
```

> 💡 Garde 7+ jours dans Loki ! 24h ne suffit pas pour un baseline pertinent.

Chaque alerte doit avoir un **runbook** :

```markdown
# Runbook : ApiBruteForce

## Vérifier

2. Combien d'users distincts essayés ?
3. Y a-t-il un succès dans le timeframe ?

## Mitiger
- Si confirmé : bloquer au firewall (iptables, Cloudflare)
```
